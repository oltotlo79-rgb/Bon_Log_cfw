# アカウント削除のご案内 — 設計ドキュメント

## 1. 概要 / 目的

### ページ概要

| 項目 | 内容 |
|------|------|
| URL | `/account-deletion` |
| ルートグループ | `app/(legal)/account-deletion/page.tsx` |
| 認証要否 | 不要（`PROTECTED_PATHS` に含めない） |
| 主たる目的 | Google Play デベロッパーポリシーが要求する「アカウント削除リクエスト手順の公開 URL」を提供する |
| 副次目的 | ログイン不要でアクセス可能な削除依頼窓口を設け、アプリをアンインストールしたユーザーも削除を依頼できるようにする |

### 対象読者

1. BON-LOG アプリのユーザー（ログイン中 / 未ログイン問わず）
2. Google Play ストア審査担当者
3. アプリをアンインストール後にアカウント削除を希望するユーザー

### 解決する問題

Google Play の 2024 年ポリシー更新により、アカウント作成機能を持つアプリは、ユーザーがアプリ外からもアカウント削除をリクエストできる手段をデベロッパーが公開する義務がある。このページはその要件を充足する。

### h2: アプリ・Web からのアカウント削除（ログイン中の方）

> BON-LOG にログインしている方は、アプリまたはウェブサイトから直接アカウントを削除できます。
>
> 1. BON-LOG を開きます
> 2. **設定** → **アカウント** の順に進みます
> 3. 「**アカウントを削除**」を選択します
> 4. 画面の案内に従って、削除操作を確定します
>
> 削除は確定後ただちに実行されます。**一度削除したアカウントを復元することはできません**のでご注意ください。

---

### h2: ログインせずに削除を依頼する（アプリをアンインストール済みの方など）

> ログインできない場合や、アプリをアンインストール済みの場合は、以下のメールアドレスまでご連絡ください。
>
> **送信先:** bon.log2026@gmail.com
>
> **メール本文に以下をご記載ください:**
>
> - 件名: 「アカウント削除希望」
> - BON-LOG に登録したメールアドレス
>
> ご連絡をいただいた後、本人確認のうえ、アカウントを削除いたします。

### h2: 削除されるデータ

> アカウントを削除すると、以下のデータが削除されます。

**削除されるデータの一覧**

- アカウント情報（メールアドレス、ニックネーム、プロフィール、生年月日など）
- 認証情報（セッション情報、外部サービスとの連携情報）
- 投稿・コメントおよびアップロードしたコンテンツ（画像・動画を含む）
- いいね、フォロー・フォロワー、ブックマーク、ブロック、ミュートの情報
- 通知、ダイレクトメッセージ・会話への参加情報
- 盆栽記録・手入れログ・カレンダー記録
- 下書き・予約投稿
- アンケートへの投票記録
- 盆栽園のレビュー
- プッシュ通知デバイス情報（モバイル・Webブラウザ）
- アクセス解析データ

> アップロードしたコンテンツはサービス上で削除され、アクセスできなくなります。バックアップやキャッシュなどの技術的仕組みにより、コンテンツが一時的にサーバー上に残存する場合がありますが、いずれ削除されます。

> また、他のユーザーがあなたの投稿を引用・リポストしていた場合、引用・リポストされたコンテンツの取り扱いは当該ユーザーの判断に委ねられます（利用規約 第11条）。

---

### h2: 保持されるデータ

> 以下のデータは、法令に基づく保存義務および会計・不正防止の目的により、アカウント削除後も一定期間保持されます。

**保持されるデータ**

- **決済・課金記録:** 有料会員として利用された際の決済記録は、あなたのアカウントとの紐付けを削除（匿名化）したうえで保持します。保持期間は、会計・税務上の法令に定められた保存期間に従います。

> 上記以外の個人情報は、プライバシーポリシー 第5条に定めるとおり、アカウント削除後も「法令で定められた期間、または紛争解決に必要な期間」は一部の情報を保持する場合があります。

`pageTitle()` ヘルパーは使わず、`title` をそのまま `string` で渡す（既存 legal ページに倣う）。

`app/robots.ts` の Disallow リストに `/account-deletion` を**追加しない**。  
デフォルトでクロール許可。Google Play 審査担当が URL を辿れる必要があるため。

### sitemap

`app/sitemap.ts` の `STATIC_PAGES` 配列に以下を追加する（`ROUTE_ACCESSIBILITY` のすぐ下を推奨）：

```
{ path: ROUTE_ACCOUNT_DELETION, changeFrequency: 'yearly', priority: 0.2 }
```

changeFrequency `'yearly'`、priority `0.2` は既存の `ROUTE_ACCESSIBILITY` と同等の扱い。  
ページ内容は法的文書であり頻繁な更新を想定しない。

`STATIC_PAGES_LAST_MODIFIED` の日付を `2026-06-25` に bump する（このページ追加タイミング）。

### メール定数の取り扱い

`lib/constants/legal/index.ts` の `tokushoho` セクションにメールアドレス `'bon.log2026@gmail.com'` が文字列リテラルで存在している。  
現時点では専用の定数化はされていない。

frontend が実装する際、以下のいずれかを選択する:

- **推奨: 定数化する** — `lib/constants/contact.ts`（新規作成）または既存の適切な定数ファイルに `SUPPORT_EMAIL = 'bon.log2026@gmail.com'` として定義し、`legal/index.ts` と `account-deletion/page.tsx` の双方から import する

## 13. 事実根拠の確認メモ（実装チェック用）
